# VC-Cheat-Typer

[![CI](https://github.com/mekks561/GTA-Vice-City-Cheat-Typer/actions/workflows/ci.yml/badge.svg)](https://github.com/mekks561/GTA-Vice-City-Cheat-Typer/actions/workflows/ci.yml)

> GTA: Vice City（罪恶都市）秘籍一键输入器 — Windows / 单文件 / 零第三方依赖

一个**单文件、零第三方依赖**的 Windows 桌面小工具：按一下快捷键，它替你在游戏里"打字"输入秘籍。

- 秘籍列表：查看 / 按分组切换 / 按使用次数排序，双击编辑
- 自定义：可添加、编辑、删除秘籍（名称 / 代码 / 分组 / 备注）
- 独立快捷键：每条秘籍单独绑定、捕获式改键（按下即录入），支持 Ctrl/Alt/Shift/Win 组合
- 冲突提示：组合键被系统或其他程序占用时，对应行标红 + 状态栏告警 + 日志说明
- 前台校验：默认只在目标游戏窗口处于前台时才发送，不会误打进聊天窗口；支持按进程名自动检测游戏
- 中文输入法免疫：发送期间自动摘掉目标窗口的 IME 关联（这是"代码没错但打不出字"的头号原因）
- 方案组：多套秘籍方案（如「默认」「速通」）一键切换，各自独立的快捷键与条目
- 游戏内悬浮提示：发送结果以不抢焦点的 toast 显示在屏幕右下角（WS_EX_NOACTIVATE）
- 注入自检：一键验证"扫描码 → 虚拟键 → WM_CHAR"全链路，无需进游戏
- 导入/导出：一键分享整份方案
- 配置持久化：方案、设置、使用统计保存在同目录 cheats.json（v2 格式，自动迁移 v1）
- 全局暂停：一键注销全部秘籍热键（默认 `Ctrl+Alt+P`），在聊天窗口/编辑器里也不怕误触
- 搜索：名称/代码/备注/分组实时过滤，与分组筛选叠加（`Ctrl+F` 聚焦，`Esc` 清空——发送中则优先停发送）
- 撤销：删除秘籍/方案后可 `Ctrl+Z` 恢复（保留最近一步）
- 冲突一键处置：右键冲突行「换一个可用键」，或一键为全部冲突项自动分配空闲组合键
- 整包备份/恢复：「⋯ 更多」里导出/导入整份配置（设置 + 全部方案 + 统计），换机、重装不丢数据
- 单条速度覆盖：编辑秘籍时可单独设置发送间隔（如慢速长代码设 100ms），默认跟随全局
- 高 DPI 适配：125% / 150% 缩放下界面按比例放大，无模糊、无控件裁剪
- 统计增强：表格新增「最近使用」列，表头可按 次数/最近/名称 排序，可清空统计，显示「今日 N 次」
- 数据安全：配置每次保存前自动留上一版（`cheats.bak.json`），损坏文件隔离留存并可一键恢复
- 可诊断：运行日志与崩溃堆栈自动写入 `logs/app.log`（窗口闪退也能查到原因）
- 发送可中断：发送中按钮原地变「■ 停止」，或按 `Esc`；暂停 / 关闭程序会立刻中止在飞发送
- 残键兜底：任何路径退出（取消 / 异常 / 关窗）都保证按键成对抬起，不会出现"角色一直跑"
- 连按去抖：同一秘籍 250ms 内重复触发只发一次（可在「⋯ 更多」→ 设置里改）
- 发送质量日志：`logs/app.log` 记录每次发送的计划/实际时长与偏差，节奏被拖慢（丢字前兆）会打 WARN
- 托盘常驻（1.8）：关闭/最小化窗口即收进系统托盘，托盘菜单 显示 / 暂停热键 / 退出；Explorer 重启后图标自动恢复
- 按游戏自动切方案（1.8）：配置「游戏规则表」（按进程名或标题匹配），游戏窗口到前台 0.8 秒后自动切换到对应方案（发送中绝不切换）
- 首次启动向导（1.8）：选参数预设 → 注入自检 → 冲突检测三步跑通，`Ctrl+F1` 随时重开
- 设置对话框（1.8）：目标关键字 / 间隔 / 方案管理 / 导入导出 / 统计 / 自动切换规则全部收进「⚙ 设置」（常规 / 输入 / 游戏 / 数据 四页），主界面只留高频操作
- 热键总览（1.8）：一张表列出全部热键、占用状态、所属方案，冲突红标，支持「重新检测占用」与导出为文本
- 配置 v3 + 迁移链（1.9）：v1 / v2 配置自动升级，升版前永久备份 `cheats.v2.bak.json`；读到更新版本配置会明确提示且**拒绝回写**；`--export-v2` / 界面导出兼容旧版配置
- 秘籍包 `.vcpack`（1.9）：导出整套秘籍分享；导入前 diff 预览（新增 / 冲突 / 相同），只导入勾选条目，冲突可覆盖可跳过，包内含 sha256 完整性提示
- 批量编辑（1.9）：列表多选（Ctrl/Shift），批量改分组 / 分配空闲热键 / 设发送间隔 / 删除（一步撤销整份快照）
- 多游戏模板（1.9）：VC 经典版 / 决定版（自动套参数）、GTA III / SA（公开秘籍文本，**未实机验证**条目灰显标注、默认不绑热键）
- 文本 / CSV 粘贴导入（1.9）：`名称,代码,热键` 或纯代码行，逐行报错带行号，预览确认后再导入

## v1.7.1 更新内容（重要修复）

| 修复 | 说明 |
|---|---|
| **权限不匹配检测** | 游戏以管理员运行而本工具不是时，Windows 的 UIPI 会**静默丢弃**注入的按键（SendInput 仍返回成功）——表现就是"按了完全没反应、日志也没有错误"。现在：① 启动即检测并显示红色告警；② 发送前拦截并明确告知原因；③ 提供「以管理员身份重启」一键修复（UAC 提权） |
| 拾取窗口修正 | 「拾取当前窗口」原实现取的是**点击按钮瞬间的前台**——那必然是本工具自己，导致目标关键字被污染、前台校验永远失败。改为优先用进程检测到的游戏窗口，其次用后台轮询记住的"最近一个非本工具前台窗口" |
| 关键字自愈 | 启动时若发现目标关键字指向本工具自身（历史误操作的产物），自动重置为「Vice City」并提示 |
| 环境诊断 | 「⋯ 更多」→「环境诊断」，或命令行 `VC-Cheat-Typer.exe --diagnose`：系统 / 权限 / 游戏进程与提权状态 / 窗口可见性 / 前台匹配 / 注入探针，一次看完 |

**"按了没反应"排查顺序**：① 工具右上角是否显示 🔴 权限告警 → 以管理员重启；② 游戏窗口是否最小化/未聚焦 → 切到游戏前台；③ 跑一次「环境诊断」；④ 看 `logs/app.log` 的 `SEND` 行。

## 一、运行环境

| 项目 | 要求 |
|---|---|
| 操作系统 | Windows 10 / 11（64 位） |
| Python | 3.8 及以上，**必须带 tkinter**（python.org 官方安装包默认包含） |
| 第三方库 | 无。只用标准库 + Windows API（ctypes） |
| 权限 | 普通用户即可；若游戏以管理员身份运行，本工具也需以管理员运行（见下文） |

本机已验证环境：Windows 11 + Python 3.10.10（64 位）。

**启动方式**（任选其一）：

```bat
:: 方式一：双击 run.bat（后台运行，无控制台窗口）

:: 方式二：命令行
"%LOCALAPPDATA%\Programs\Python\Python310\pythonw.exe" vc_cheat_typer.py

:: 方式三：先跑一次自检（推荐首次使用时执行）
"%LOCALAPPDATA%\Programs\Python\Python310\python.exe" vc_cheat_typer.py --selftest
```

自检会验证：结构体尺寸、组合键解析、真实键盘注入落字、热键注册与冲突返回码、GUI 启动。
本机自检输出：`自检结果: 全部通过`。

## 二、使用前提（游戏侧）

1. **版本**：经典 PC 版 GTA: Vice City（1.0 版最佳）；The Definitive Edition（决定版）的键盘输入秘籍大部分同样有效，但输入窗口与帧率行为不同，间隔建议调到 60ms 以上。
2. **游戏必须处于前台**：本工具是"替你打字"，游戏窗口不在前台就收不到（工具默认会校验并提示）。
3. **处于游戏内画面**：主菜单 / 读档画面无效；正在播过场动画时输入可能被吞。
4. **小技巧**：先按 `Esc` 打开暂停菜单再触发秘籍，可以避免"打字的过程"在游戏里触发跳跃、加速跑等按键副作用（官方维基推荐做法），输完再按 `Esc` 返回。
5. **单机专用**：请勿在联机 / 含反作弊的环境使用。本工具只发送标准键盘事件，不读写游戏内存、不改游戏文件。
6. **成功标志**：屏幕左上角出现 **"Cheat Activated"**。

## 三、快速上手

## 四、快捷键冲突提示（工作原理）

- 工具用 `RegisterHotKey` 注册全局热键，该 API 天然独占：
  - **与其他程序冲突** → 系统返回错误码 1409，对应行标红，状态栏显示"⚠ N 个快捷键不可用"，日志会点名占用组合键；
  - **同一列表内两条秘籍绑了同一个键** → 直接判为冲突，不会注册第二个；
  - **权限不足**（游戏以管理员运行而工具不是）→ 提示以管理员身份运行。
- 常见占用者：输入法切换键、显卡/录屏软件、F12（系统调试器）、其他按键精灵类工具。**双击对应行 → 捕获新键**即可解决；
  也可以**右键冲突行 →「换一个可用键」**让工具自动挑一个空闲组合键，或右键 →「自动分配全部冲突项」一次清完。
- 防呆设计：单个字母/数字不允许作为无修饰热键（否则游戏里按 A 就触发秘籍、打不了字），捕获时会直接拒绝。

## 五、前台校验与游戏检测

- **自动检测**：工具每 3 秒扫描一次顶层窗口，按进程名（gta-vc.exe 等）识别游戏；状态栏显示 🟢 游戏运行中 / ⚪ 未检测到。检测命中时，前台校验直接放行，无需配置关键字。
- 「目标窗口关键字」按**窗口标题或进程名**做包含匹配（不区分大小写），逗号分隔可写多个；检测不到游戏时用它兜底。
- 「拾取当前窗口」按钮：把当前前台窗口的标题一键填入关键字；
- 每个字符发送前都会复查前台窗口是否还是同一个 HWND，切屏即中止，绝不把秘籍打进别的窗口。

## 六、注入自检

点主界面「注入自检」：工具会短暂弹出一个约 1 秒的小窗（隐藏原生 Win32 窗口），自动输入 `ASPIRINE` 并回读校验，toast + 日志报告结果。

> 为什么不用 Tk 文本框做验证：Tk 的窗口自行管理输入法上下文，在中文 IME 环境下注入的扫描码会被转成 VK_PACKET（WM_KEYDOWN 229），一个字符都收不到——这是 Tk 显示层的问题，不代表注入失效（游戏走 DirectInput 读设备状态，是另一条通道）。原生窗口没有这层干扰，结果可信。

## 七、参数调优

| 参数 | 默认 | 说明 |
|---|---|---|
| 每字间隔 | 45ms | 游戏按帧轮询键盘，**发太快会丢字**（一个字符同一帧内按下又抬起会被整帧漏掉）。出现丢字 → 调到 60~100ms；低帧率/决定版建议 60ms+（或直接用「决定版」预设） |
| 单条间隔覆盖 | 跟随全局 | 编辑秘籍时可为单条单独设 20–300ms（如超长代码 `OURGODGIVENRIGHTTOBEARARMS` 设 80ms 更稳），不影响其他秘籍 |
| 发送前延迟 | 180ms | 触发后等手指离开修饰键，避免 Ctrl/Shift 干扰 |
| 绕开中文输入法 | 开 | 发送期间临时摘掉目标窗口 IME 关联，发完自动恢复 |
| 大写发送 | 关 | 游戏对秘籍不区分大小写，小写更稳（不碰 Shift） |
| 悬浮提示 | 开 | 游戏内 toast；WS_EX_NOACTIVATE，绝不抢走游戏焦点 |

## 八、技术实现要点（为什么这样做）

1. **SendInput + 扫描码（KEYEVENTF_SCANCODE）**：GTA VC 经典版通过 DirectInput 轮询键盘设备状态，
   `PostMessage`/`SendKeys` 这类消息级输入它读不到；扫描码注入发生在键盘驱动层，DirectInput 才能看见。
2. **按下与抬起分两次调用，中间保持 ≥25ms**：保证跨帧可读，这是"自动打字丢字"的最常见原因。
3. **RegisterHotKey 线程消息泵**：注册/注销必须在同一线程完成，工具用独立泵线程 + `PostThreadMessage` 唤醒，
   主线程（UI）通过事件队列收发，互不阻塞。
4. **ImmAssociateContext(hwnd, NULL)**：中文键盘布局会给窗口挂 IME 输入上下文，把注入击键转成 VK_PACKET 吞掉
   （实测不处理时目标窗口一个字符都收不到）。发送期间摘除、发完挂回。
5. 全部 Windows API 通过 ctypes 直接调用，无 DLL、无注册表、无网络。

## 九、常见问题

| 现象 | 处理 |
|---|---|
| 按了快捷键没反应 | 看状态栏：冲突 → 双击改键；前台不对 → 拾取当前窗口；游戏在读档/过场 → 回到自由画面 |
| 提示"键盘注入失败 拒绝访问" | 游戏以管理员运行 → 工具也右键"以管理员身份运行" |
| 秘籍输入后游戏只收到一部分字母 | 每字间隔调大（60~100ms），或游戏切窗口模式跑 |
| 双击工具没反应 | Python 没装或没带 tkinter：装 python.org 的 3.8+，勾选 "tcl/tk and IDLE" |
| 提示"工具已在运行" | 已有实例在跑，看任务栏 |
| 想恢复内置 28 条 | 主界面「恢复默认」按钮（自定义内容会清空） |
