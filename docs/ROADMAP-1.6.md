# VC-Cheat-Typer 1.6 版本规划

> 基线：v1.5（commit b1ba6c4）｜ 规划日期：2026-11-04 ｜ 目标发布：2026-11-20（周五）
> 文档性质：执行用规划，任务可直接拆为 issue / 提交

## 一、版本目标

### 1.1 一句话定位

**v1.6 = 安全阀 + 可诊断 + 可交付。** 不堆新功能，把 1.5 已经做出来的能力补齐"出错时怎么办"的三道防线。

### 1.2 为什么是这个方向（基于代码现状的判断）

| 现状观察 | 由此得出的问题 |
|---|---|
| 2068 行单文件、85 个方法，1.5 一口气加了 7 个功能 | 功能面已够用，继续堆功能边际收益递减 |
| 无全局暂停开关（`grep 暂停` = 0） | **安全隐患**：热键常驻，在聊天窗口/编辑器里误触即乱打字，只能关程序 |
| 无 excepthook、无日志文件（`grep 日志文件` = 0） | **不可诊断**：PyInstaller `--windowed` 下崩溃零输出，用户只能报"打不开" |
| `load_store` 解析失败静默回退默认 | **静默丢配置**：cheats.json 损坏后用户的自定义秘籍无声消失 |
| 无搜索（`grep 搜索` = 0），只有分组下拉 | 28 条尚可，用户加到 60+ 条后定位困难 |
| 删除无撤销（`grep undo` = 0） | 误删方案（含整套秘籍）不可恢复 |
| 冲突只标红，无处置手段 | 用户看到"冲突"但不知道换什么键 |
| 无 DPI 感知（`grep dpi` = 0） | Win 125%/150% 缩放下 tk 界面模糊，首屏观感差 |
| 无 CI，靠人工跑 ruff + unittest | 每次改动缺少自动回归防线，1.5 曾靠人工抓到 `persist` 重复定义 |
| 远端 0 issue | 暂无外部需求压力，可自主排期 |

### 1.3 成功标准（发布门槛，全部满足才发 1.6）

1. 暂停状态下按任意秘籍热键 **零注入**；恢复后立即生效
2. 任意崩溃/异常在 `logs/` 留下可读堆栈；windowed exe 同样有效
3. 故意写坏 `cheats.json` 后启动：生成 `cheats.corrupt-*.json` 副本 + 界面提示，且工具可正常使用
4. 搜索 + 分组可叠加过滤，`Ctrl+F` 可直接聚焦
5. 删除秘籍/方案后可 `Ctrl+Z` 恢复
6. 冲突行可一键改到可用键，且不与已有绑定重复
7. 100% / 125% / 150% 三档缩放截图无模糊、无控件裁剪
8. 单元测试从 12 条增至 **≥22 条**；ruff 0 告警；`--selftest` 连跑 3 次全过
9. Release 附带 `VC-Cheat-Typer.exe` + SHA256 校验文件

## 二、功能与改进点（按优先级）

### P0 — 发布必须（缺一不发）

| 编号 | 功能 | 具体做法 | 验收标准 |
|---|---|---|---|
| P0-A | **全局暂停 / 紧急停止** | 新增 `settings.pause_hotkey`（默认 `Ctrl+Alt+P`，可改，复用现有 `HotkeyCapture`）；暂停时注销全部秘籍热键，恢复时整体重注册；状态栏与工具栏按钮同步变红；切状态弹 toast | 暂停后按 F1~F11 无任何字符落地；恢复后正常；暂停键自身冲突时按现有机制提示 |
| P0-B | **崩溃可诊断** | `sys.excepthook` + `threading.excepthook` → 写 `logs/app-YYYYMMDD.log`（单文件上限 1MB，保留 3 份）；崩溃弹窗显示日志路径；工具栏加"打开日志" | 人为 raise 后日志含时间/线程/堆栈；exe 崩溃后日志存在 |
| P0-C | **配置容错与备份** | `load_store` 解析失败 → 原文件改名 `cheats.corrupt-<时间戳>.json` 并提示；每次 `save_store` 前把上一版复制为 `cheats.bak.json`；界面加"从备份恢复" | 写坏 JSON 后启动不丢原文件、可一键回滚上一版 |
| P0-D | **搜索** | 顶部搜索框，实时过滤 名称/代码/备注（大小写不敏感）；与分组下拉**叠加**生效；`Ctrl+F` 聚焦、`Esc` 清空；显示"N / 总数" | 输入 `health` 命中"满血"；搜索 + 分组交叉结果正确 |
| P0-E | **单步撤销** | 删除秘籍 / 删除方案 / 批量操作前入栈（仅保留最近 1 步）；`Ctrl+Z` 或工具栏"撤销"恢复；恢复后自动重新注册热键 | 删方案 → 撤销 → 秘籍与热键全部回原样 |

### P1 — 应该做（进度允许则全做）

| 编号 | 功能 | 具体做法 | 验收标准 |
|---|---|---|---|
| P1-F | **冲突处置** | 冲突行右键菜单"换一个可用键"：按候选序列（F1–F11 → Shift+F1… → Ctrl+Shift+F1…）逐个试注册，取第一个成功且未被占用的；另有"全部冲突项自动分配" | 手工占用 F1 后，右键可将该行改到可用键，且列表内无重复 |
| P1-G | **全量备份 / 恢复** | 与现有"导出方案"并列新增"导出整包/导入整包"（settings + 全部方案 + 统计）；导入前校验 `app`/`version` 并二次确认覆盖 | 备份 → 改配置 → 恢复 → 内容完全一致 |
| P1-H | **单条秘籍速度覆盖** | cheat 级可选 `interval_ms`（0/缺省 = 跟随全局）；编辑对话框"高级"折叠区 | 某条设 100ms，实测发送时长 ≈ 字符数 × 100ms（±10%） |
| P1-I | **高 DPI 适配** | 启动即 `SetProcessDpiAwareness(1)`；按 `root.winfo_fpixels('1i')` 调整字体与表格列宽 | 125%/150% 截图无模糊、无裁剪 |
| P1-J | **统计增强** | 表格增"最近使用"列；表头可按 次数/最近 排序；"清空统计"；状态栏显示"今日 N 次" | 发送后 last 与今日计数立即更新 |
| P1-K | **CI 自动回归** | `.github/workflows/ci.yml`：`windows-latest`，Python 3.10 + 3.12 矩阵，跑 `ruff check` + `unittest` + `py_compile`；README 加状态徽章 | push 后 Actions 全绿；故意改坏一处能被拦下 |

### P2 — 可选（有余量再做，不阻塞发布）

| 编号 | 功能 | 说明 |
|---|---|---|
| P2-L | 发送中可取消 | 暂停键 / Esc 中止剩余字符（需在 `_send_worker` 加共享停止标志） |
| P2-M | 英文 README + 截图 | `README.en.md`，面向 GitHub 国际访客；附界面截图 |
| P2-N | 构建脚本 + 校验和 | `build.ps1` 一键构建；Release 附 `VC-Cheat-Typer-SHA256.txt`；顺带评估 onedir 版（启动更快、误报率略低） |
| P2-O | 游戏检测联动方案 | 检测到游戏时自动切换到指定方案（当前检测只做状态显示与放行） |

### 明确不做（Out of Scope，避免范围膨胀）

- 界面框架重写（PySide/Qt）、Web UI —— 1.5 评估已否决，运行时零依赖是核心资产
- 自动更新 / 联网校验 —— 引入网络与签名成本，工具型需求不需要
- 宏录制、连招序列、多步脚本 —— 偏离"秘籍输入器"定位
- 多语言界面（仅英文 README 文档）、云同步、账号体系
- 代码签名证书 —— 成本高于收益，改为"源码可自建 + SHA256"
- 决定版（Definitive Edition）专项适配 —— 缺少游戏副本做真机验证，仅保留参数预设

## 四、风险与依赖

### 4.1 风险登记

| # | 风险 | 概率/影响 | 缓解措施 |
|---|---|---|---|
| R1 | 暂停键与系统/其他软件冲突，导致"暂停失效" | 中 / 高 | 复用现有 1409 冲突检测并在状态栏明示；暂停键可自定义；默认选冷门组合 `Ctrl+Alt+P` |
| R2 | 暂停/恢复时热键注册时序出错（重复注册、漏注册） | 中 / 中 | 统一走 `HotkeyEngine.apply()` 单一入口（先全注销再注册）；补 2 条单测覆盖"暂停→恢复→再暂停" |
| R3 | DPI 感知开启后布局错位、控件被挤出 | 中 / 中 | 1.5 已有"grid 挤掉导入按钮"的前车之鉴；改后用 100/125/150 三档截图逐项核对 |

| R6 | 杀软误报加剧（新增文件写入行为） | 高 / 中 | Release 说明保留免责与自建指引；提供 SHA256；不引入额外加壳 |
| R7 | 时间风险：年底事务 + 兼职节奏 | 中 / 高 | 只保 P0，P1 可裁剪；发布日固定 11/20，范围随进度浮动 |

## 七、版本号与兼容性

- 版本号语义：功能新增 + 无破坏变更 → `1.6.0`；仅修复 → `1.6.x`
