# VC-Cheat-Typer 1.7 → 2.0 路线规划

> 基线：v1.6（commit `7307be2`，2026-11-05 发布）｜ 规划日期：2026-11-05
> 文档性质：执行用规划，任务可直接拆为 issue / 提交
> 上游文档：`docs/ROADMAP-1.6.md`（已完成）

---

## 零、现状基线（规划的出发点）

| 维度 | 现状 | 对路线的影响 |
|---|---|---|
| 代码结构 | `vc_cheat_typer.py` 单文件 **2900 行**，`CheatApp` 单类约 1200 行 | 加功能的边际风险快速上升 → **1.7 必须先解耦**，否则 1.8 的 UI 改动不敢做 |
| 依赖 | 零第三方运行时依赖（tkinter + ctypes 手写 Win32） | 这是核心资产（免装环境、杀软面小、可审计）→ **全线不引入 pip 运行时依赖** |
| 测试 | 45 条单测（纯函数）+ `--selftest`；`build/gui_test.py` 21 项**仅本地**，且 `build/` 会被清理 | GUI 回归无 CI 保护 → 1.7 补 |
| 输入链路 | `SendInput` 逐字符 fire-and-forget；**无取消、无并发保护** | 连按两个热键会交错出乱码 → 1.7 P0 |
| 配置 | `version: 2`，字段可选即兼容 | 1.7/1.8 保持 v2；1.9 升 v3 并留降级出口 |
| 检测能力 | `find_game_window()` 每 3s 枚举窗口，**仅用于状态显示/放行** | 已具备"切方案"的原料，1.8 只差规则表 |
| UI 密度 | 工具栏两行 + 「⋯ 更多」菜单（1.6 因挤爆才收进去） | 已到 tk 布局极限 → 1.8 改设置对话框 |
| 1.6 遗留 | P2 四项全未做：发送中取消、英文 README、`build.ps1`、游戏自动切方案 | 直接成为 1.7/1.8 的输入 |

**版本主线**：`1.7 拆得开` → `1.8 用得顺` → `1.9 装得下` → `2.0 拎得走`。

## 二、v1.7 — 输入可靠 + 工程解耦

### 2.1 定位与理由

**不新增任何面向用户的功能。** 只做两件事：把发送链路做到"可信"（可取消、不交错、不留残键），把单文件拆成包（后续三个版本的改动才有地方落）。
判断依据：连按 `F1` `F8` 两个热键时，两条 worker 线程会同时 `SendInput`，输出必然交错成乱码——这是**当前真实存在的 bug**，不是假想需求；而 2900 行单文件已经让 1.6 的「导入方案」按钮截断这类小改都要全文件搜一遍。

### 2.2 必做（P0，缺一不发）

| 编号 | 功能 | 做法 | 验收标准 | 估时 |
|---|---|---|---|---|

## 三、v1.8 — 场景化与可用性

### 3.1 定位与理由

v1.7 之后工具已经"可信"，但**第一次打开仍然要配**：改键、设延迟、试注入，全在密集的两行工具栏里。1.8 把「配置」从主界面搬走，把「场景」自动接上——目标用户是"想玩游戏的人"，不是"愿意读文档的人"。

## 四、v1.9 — 内容可流通

### 4.1 定位与理由

到 1.8，单个用户的自用体验已经完整。继续加"自己用"的功能收益趋零，但**内容侧**仍是空的：28 条秘籍写死在代码里，用户想加 GTA III / SA 的秘籍只能一条条手工录；别人调好的键位/分组无法分享。1.9 把"秘籍"从程序里的一块常量，变成可导入导出、可批量操作的**数据资产**。

## 五、v2.0 — 通用输入平台

### 5.1 定位与理由

1.7–1.9 做完，这个工具在"VC 秘籍输入"这一件事上已经到顶。2.0 的价值不在功能清单，而在**把输入引擎从业务里剥出来**：`SendInput + IME 绕行 + 热键总线 + 前台判定` 这套东西，任何"给按键类游戏/软件注入文本"的场景都能用（GTA 系列之外、老游戏、模拟器、甚至直播时的固定文本）。
2.0 = **可被复用**，不是"功能更多"。

### 6.2 配置兼容矩阵

| 程序版本 | 配置版本 | 读 1.6 配置 | 降级 / 回退路径 |
|---|---|---|---|
| v1.7 | v2 | ✅ 直接读 | 覆盖旧 exe 即可 |
| v1.8 | v2（+ `games` 可选字段） | ✅ 直接读 | 同上；`games` 被旧版忽略 |
| v1.9 | **v3**（自动迁移） | ✅ 自动迁移 + 备份 | `--export-v2` 导出兼容包 |
| v2.0 | v3 | ✅ 复用迁移链 | `--export-v2`；保留 1.9 exe 可回退 |

**三条铁律**

1. **配置只升不降，但必须留出口**：任何升版都自动备份上一版文件，并提供显式导出旧格式的命令。
2. **新字段一律可选**：缺省 = 旧行为。允许"程序新、配置旧"，不允许"程序旧、配置新"静默降级（提示升级）。
3. **迁移函数纯化**：`migrate_store(raw) -> dict` 不碰文件系统，便于用 5 份真实历史配置做回归样本。

### 6.3 发布纪律（每版相同）

- tag `vX.Y` → Release 名称 `VC-Cheat-Typer vX.Y`（不附加描述文字）→ 资产 `exe` + `SHA256.txt`。
- Release 说明固定含：「从上一版升级：直接覆盖 exe，配置自动沿用/迁移；回退需保留旧 exe + 备份文件」。
- 每版发布前跑：`ruff` 0 告警、单测全过、`--selftest` 连跑 3 次、GUI 冒烟、三档缩放截图（100/125/150）。
- 1.x 内不做破坏性变更；2.0 允许一次，但必须自动迁移 + 出口 + 三路径实测。

## 九、累计明确不做（Out of Scope）

沿用 1.6 结论并追加：

- 界面框架重写（Qt/PySide/Web UI）——2.0 只是把 core 抽出，不换 UI 工具包；
- 内存修改器 / 修改游戏数据 / DLL 注入——法律与反作弊风险，且偏离"输入工具"定位；
- 自动更新下载、遥测、云同步、账号体系；
- 代码签名证书（成本 > 收益，维持"源码可自建 + SHA256"）；
- 联机 / 含反作弊环境支持（README 永久免责声明）；
- 宏录制、连招序列、定时循环（2.0 的策略引擎只覆盖"单次输入的质量"，不做自动化脚本）。

## 十、一句话总结

**1.7 把地基浇筑好（拆包 + 输入可信），1.8 把门面做顺（托盘 + 自动切 + 设置页），1.9 把内容做成资产（包 + 批量 + v3），2.0 把引擎抽出来复用（core + 策略 + 目标规则）。**
