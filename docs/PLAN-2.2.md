# v2.2「Nova UI」规格与验收标准

> 基线：v2.1（tag `v2.1`，commit `e5cd779`）
> 本文件是**需求规格 + 验收契约**，不是事后总结；验收标准在开发前定死，测试按此写。

---

## 0. 技术栈取舍（必须先讲清楚）

需求要求「引入新的技术栈、全面重做 UI」。本项目有两条**跨版本不变量**：

1. 零第三方**运行时**依赖（`CONTRIBUTING.md` §3 / 路线图 §8）；
2. `core` 零 GUI 依赖、UI 不直接调 Win32。

同时路线图 §9 明确把「界面框架重写（Qt / PySide / Web UI）」列为 **Out of Scope**。

若引入 PySide6 / QtWebView：exe 会从 ~10 MB 涨到 60 MB+、需要打包 Qt 运行时、CI 要装依赖、
`pip install -e .` 的 `dependencies=[]` 失效、208 条 GUI 冒烟与三产物形态全部要重做，且**不可回退**。
这与「保持核心业务流程稳定」和「失败可回退」直接冲突。

**因此本版引入的"新技术栈"是项目自研的 UI 基础设施层 `vcct/ui/`**：

| 层 | 技术 | 说明 |
|---|---|---|
| 设计令牌 | `theme.py` | 单一数据源：颜色 / 间距 / 字号 / 圆角 / 密度；浅色 + 深色双主题；WCAG 对比度计算 |
| 组件 | `components.py` | 声明式组件工厂：卡片、胶囊、分段控件、空状态、命令栏、状态条 |
| 布局 | `shell.py` | 新骨架：侧边导航 + 顶部命令栏 + 内容区 + 底部状态中心 |
| 交互 | `commands.py` | `Ctrl+K` 命令面板（模糊匹配 + 纯键盘执行） |

它是**新的 UI 架构范式**（令牌驱动 / 声明式 / 命令优先），仍是标准库 + tkinter/ttk，
不新增任何 pip 依赖，不改动 `vcct/core/`，并且保留 `--classic-ui` 一键回退到 1.7～2.1 的布局。

> 若确需 Qt / WebView，属于**重新立项**：需用户显式确认接受「放弃零依赖、放弃可回退、重做发布形态与 CI」，
> 应另起 v3.0，不在 2.2 内夹带。

## 1. 升级目标

| # | 目标 | 可衡量结果 |
|---|---|---|
| G1 | 视觉现代化 | 从 1.7 的「工具条 + 表格」升级为令牌驱动的卡片式布局；浅/深双主题；所有颜色出自单一令牌表 |
| G2 | 命令优先 | 常用操作不必层层找菜单：`Ctrl+K` 命令面板覆盖 ≥20 个既有动作，全程键盘可达 |
| G3 | 信息层级 | 侧边导航把「秘籍 / 热键 / 内容 / 数据 / 帮助」分区；底部状态中心聚合游戏、热键、发送状态 |
| G4 | 核心零改动 | 发送引擎、热键注册、托盘、包、迁移链、CLI 一行不改；UI 只调用既有业务方法 |
| G5 | 可回退 | `--classic-ui` / `settings.ui_mode=classic` 恢复 1.7～2.1 原布局与配色；升级零感知 |

**明确不做**：不换 UI 工具包、不改配置版本（仍 v3）、不改包格式、不联网、不写游戏内存、不做动画堆砌。

## 3. 页面与交互变更

### 3.1 旧版（1.7～2.1，`--classic-ui` 可回退）

```
┌─────────────────────────────────────────────┐
│ 标题 / 版本 / 游戏状态                       │
│ [方案▾][分组▾][搜索] [设置][热键][更多▾]    │
│ ── 表格（8 列）─────────────────────────────│
│ [发送][停止][添加][编辑][删除][批量▾]        │
│ ── 日志 ────────────────────────────────────│
└─────────────────────────────────────────────┘
```

### 3.2 Nova（2.2 默认）

```
┌──────┬──────────────────────────────────────────────┐
│      │  ⌘K 命令面板入口    [游戏状态胶囊][主题][⋯]  │  ← 顶栏
│ 侧栏 ├──────────────────────────────────────────────┤
│ 导航 │  ┌ 内容卡片 ────────────────────────────┐    │
│      │  │ 原有控件树（方案/搜索/表格/操作/日志）│    │  ← 不重建，只换父容器
│ 秘籍 │  └───────────────────────────────────────┘    │
│ 热键 │                                              │
│ 内容 ├──────────────────────────────────────────────┤
│ 数据 │  游戏 ●  热键 ●  发送 ●  配置 ●  语言 ●     │  ← 状态中心
│ 帮助 └──────────────────────────────────────────────┘
```

| 变更 | 旧 | 新 | 回退 |
|---|---|---|---|
| 布局骨架 | 单列工具条 | 侧栏 + 顶栏 + 内容卡片 + 状态中心 | `--classic-ui` |
| 配色 | 硬编码在 `const.C` | 设计令牌驱动，浅/深双主题，启动时注入 `C` | `theme=classic` 或旧模式 |
| 密度 | 固定 | 舒适 / 紧凑两档（间距令牌） | 设置项 |
| 找功能 | 菜单层层点 | `Ctrl+K` 命令面板，输入即筛、↑↓ 选、Enter 执行、Esc 关 | 旧菜单仍完整保留 |
| 导航 | 无 | 侧栏 5 个分区，点击执行对应的既有命令 | 旧模式不显示侧栏 |
| 状态 | 分散在标题/状态栏/日志 | 底部状态中心聚合 5 个状态胶囊 | 旧状态栏保留 |

**关键实现约束**：新骨架只**替换 `outer` 的父容器**并添加外壳，
原有控件变量（`self.tree` / `self.btn_send` / `self.lbl_state` …）与全部事件绑定保持不变，
因此 208 条既有测试与所有业务流程继续成立。

### 3.3 命令面板（新交互）

- 触发：`Ctrl+K`（全窗口）/ 顶栏按钮；`Esc` 关闭、↑↓ 选择、`Enter` 执行、输入实时过滤
- 数据源：`commands.py` 的 `CommandRegistry`，每条命令绑定一个既有 `CheatApp` 方法
- 覆盖 ≥20 项：添加/编辑/删除/发送/停止/暂停/重注册热键/热键总览/设置/向导/
  导入包/导出包/文本导入/模板/批量操作/环境诊断/发送历史/清空统计/恢复默认/检查更新/切换主题
- 模糊匹配：子序列匹配 + 中文/英文关键词，不依赖第三方库

## 4. 现有功能及数据兼容要求

| 项 | 要求 | 保障方式 |
|---|---|---|
| 配置 | 仍 **v3**；新设置 `ui_mode`（默认 `nova`）、`theme`（默认 `light`）、`density`（默认 `comfortable`）全部可选，缺省 = 旧行为 | 沿用 `normalize_store` 白名单；测试覆盖 v1/v2/v3 配置读入 |
| 数据丢失 | 零丢失：方案 / 热键 / 统计 / 包记录 / 历史 / targets / strategies 一字不改 | 本版不碰 `store.py` 的持久化字段；三条升级路径回归继续跑 |
| 功能可达 | 旧版每一个按钮/菜单项在新版**仍然可达**（命令面板或侧栏或原工具条） | 命令注册表断言覆盖所有既有入口；GUI 冒烟构建两种模式 |
| 热键/发送 | 注册、暂停、取消、前台校验、IME、策略、钩子行为逐项不变 | 核心代码零改动 + 既有 208 条测试全绿 |
| 回退 | 启动参数 `--classic-ui` 或设置里切回 classic，重启即恢复 1.7～2.1 布局 | 双路径测试：两种模式都能完整构建主窗口并调用业务方法 |
| 打包 | onefile / onedir / console CLI 三产物形态不变，各自 SHA256 | `build.ps1 -OneDir` 三产物实测 |
| 语言 | 2.1 的中英表驱动继续生效，新 UI 文案进 `i18n.EN_TEXT` | 两种语言 × 两种模式构建测试 |

## 5. 验收标准（可量化，测试即契约）

### 5.1 视觉一致性

| # | 标准 | 自动化验证 |
|---|---|---|
| V1 | 所有颜色来自 `theme.py` 的令牌表；除 `theme.py`（令牌源）外，新 UI 模块内**零硬编码 `#RRGGBB`** | AST + 正则扫描 `vcct/ui/*.py` |
| V2 | 正文/背景对比度 ≥ **4.5:1**（WCAG AA），主按钮文字 ≥ 4.5:1 | `contrast_ratio()` 计算并断言，浅/深两套主题都测 |
| V3 | 浅/深主题令牌键集合完全一致，切换不缺键 | `set(light) == set(dark)` |
| V4 | 间距/字号按密度令牌统一，组件不自行写死 padx/pady 魔数 | 组件从 `tokens.spacing` 取值；测试断言缩放线性 |
| V5 | 100% / 125% / 150% DPI 三档下无控件裁切 | `ui_scale()` 三档构建冒烟（人工截图复核项） |

### 5.2 交互流畅度

| # | 标准 | 自动化验证 |
|---|---|---|
| I1 | 命令面板输入到结果刷新 **< 50 ms** | 100 次输入计时取 P95 |
| I2 | 全键盘可达：`Ctrl+K` → 输入 → ↑↓ → `Enter` → `Esc` | 事件模拟测试 |
| I3 | 主题/密度切换 **< 200 ms**，且不重建业务控件树 | 计时 + 断言 `self.tree` 对象身份不变 |
| I4 | 无主线程阻塞：发送仍在工作线程；命令面板不 `sleep` | AST 禁止新 UI 模块出现 `time.sleep` / `update()` 死循环 |
| I5 | 两种 UI 模式下所有业务方法可调用且不抛异常 | GUI 冒烟分别构建并调用若干命令 |

### 5.3 响应速度

| # | 标准 | 自动化验证 |
|---|---|---|
| R1 | 主窗口构建（含 Nova 骨架）**< 1.5 s** | `perf_counter` 计时；测试机上留 2× 余量 |
| R2 | 1000 条秘籍渲染 **< 300 ms** | 构造 1000 条调用 `refresh_tree()` 计时（含过滤） |
| R3 | 命令面板 200 条命令过滤 **< 20 ms** | 计时 P95 |
| R4 | 发送触发到工作线程启动 **< 50 ms**（不改变异步模型） | 既有异步结构不变，代码审查 + 单飞测试 |

> 性能断言在 CI 上采用宽松阈值（本机基准的 3 倍）避免机器波动误报；精确数值写入测试日志。

### 5.4 回归底线

- 208 条既有单测 **全绿**（本版只增不减，实际达 228 条）
- `ruff check` 0 告警
- `--selftest` 全过（新增 `[2i]` 段验证 UI 层）
- `-X faulthandler` 全量测试 **0 次 access violation**
- 三产物 exe / zip 自检 + `sha256sum -c` 通过；CI 3.10 / 3.12 双绿

### 5.5 本机实测（`tests/test_v2_2.py` 打印）

| 指标 | 规格 | 实测 |
|---|---|---|
| WCAG 最小对比度（浅 / 深） | ≥4.5:1 | 5.26:1 / 6.81:1 |
| 命令搜索 P95（200 条 ×100 次） | <20 ms | 0.1 ms |
| 主题切换（不重建控件） | <200 ms | 6.4 ms |
| 主窗口构建（nova / classic） | <1.5 s | 79.3 ms / 57.3 ms |
| 1000 条秘籍渲染 | <300 ms | 10.3 ms |

CI 断言取规格值 3 倍余量，避免机器波动误报。

## 6. 待真机人工验收

主题切换后的实际观感、深浅主题在 125%/150% DPI 的排版、`Ctrl+K` 手感、
侧栏在窄窗口（< 900px）的折叠、托盘与 Nova 状态中心的同步、三档缩放截图。
自动化只能保证结构/对比度/耗时，观感仍需人眼过一遍。

已知无害噪音：测试套件在同一进程内创建多个 `Tk()` 根时，ttk 的
`<<ThemeChanged>>` 偶尔会投递到已销毁的窗口，打印一行
`can't invoke "event" command`。真实程序只有一个根窗口，不会出现；
`rc=0`、0 次 access violation，不影响验收。
