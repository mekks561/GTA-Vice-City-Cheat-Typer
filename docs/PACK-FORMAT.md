# .vcpack 秘籍包格式规范（v1）

> 适用：VC-Cheat-Typer v1.9 及以上｜解析器 `vcct/packs.py`｜零第三方依赖

## 1. 文件与定位

单个 UTF-8 JSON 文件，扩展名建议 `.vcpack`（`.json` 亦可）。用于**把一整套秘籍分享给别人**，或给自己做内容备份。它只装秘籍，不装设置 / 热键注册结果 / 使用统计；整份配置备份请用「⋯ 更多 → 导出整包」。

## 2. 完整示例

```json
{
  "format": "vcct-pack",
  "pack_version": 1,
  "name": "VC 经典版 · 社区补全",
  "author": "someone",
  "game": "VC 经典版",
  "min_app": "1.9.0",
  "exported_at": "2026-11-08 09:30:00",
  "cheats": [
    {
      "id": "a1b2c3d4",
      "name": "满血",
      "code": "ASPIRINE",
      "hotkey": "F4",
      "group": "生存",
      "note": "开车时同时修轮胎",
      "interval_ms": 0,
      "verified": true
    }
  ],
  "sha256": "…64 位十六进制…"
}
```

## 3. 字段定义

### 顶层（必填 4 项）

| 字段 | 类型 | 说明 |
|---|---|---|
| `format` | string | 必须精确等于 `"vcct-pack"`，否则拒绝导入 |
| `pack_version` | int | 包格式版本，目前只支持 `1`。**独立于程序版本**，将来改结构不动 APP_VER |
| `cheats` | array | 至少 1 条合法秘籍；代码不得重复 |
| `sha256` | string | 可选但强烈建议。见 §5 |

### 顶层（可选元数据）

| 字段 | 说明 |
|---|---|
| `name` | 包名，导入后写进「已安装记录」；缺省 `未命名秘籍包` |
| `author` | 作者 |
| `game` | 适用游戏模板名；导入时写到每条秘籍的 `game` 字段 |
| `min_app` | 建议的最低程序版本（如 `1.9.0`）。低于它只警告，不阻断 |
| `exported_at` | 导出时间字符串 |

**未知字段一律忽略**（不报错），方便第三方手写包与未来扩展。

### `cheats[]` 条目

| 字段 | 必填 | 说明 |
|---|---|---|
| `code` | ✅ | 秘籍代码，只含 `A–Z` / `0–9`，程序会转大写并去空格；空或不合法则该条被丢弃（整包都不合法 → 拒绝） |
| `name` | — | 缺省 = code |
| `hotkey` | — | 如 `F4` / `Ctrl+Shift+F2`。非法或不安全（无修饰键的单字母）由导入器校验；包内允许留空 |
| `group` | — | 缺省 `自定义` |
| `note` | — | 备注 |
| `interval_ms` | — | 单条发送间隔 0–300；0 = 跟随全局；越界归 0 |
| `verified` | — | 是否实机验证过，缺省 `true`。**第三方模板应设为 `false`**，UI 会灰显标注 |
| `id` | — | 本地 id；导入新条目时会重新生成，覆盖已有条目时保留原 id |

## 4. 校验规则（`validate_pack`）

按顺序检查，命中即拒绝：

1. 顶层不是 JSON 对象 → 拒绝；
2. `format != "vcct-pack"` → 拒绝；
3. `pack_version` 缺失 / 非整数 / 不在 `1..1` → 拒绝；
4. `cheats` 不是数组或为空 → 拒绝；
5. 归一化后一条都不剩，或包内 `code` 重复 → 拒绝。

**只产生警告、不阻断**的情况：

- `sha256` 缺失或与内容不符（说明包被手工改过）；
- `min_app` 高于当前程序版本。

> 为什么 sha256 不做门禁：验收要求「导出 → 手工改两条 → 再导入」能往返一致。若校验不符就拒绝，用户改包后只能重新算哈希，与"可手写包"的初衷冲突。所以它是**完整性提示**，不是准入条件。

## 5. sha256 计算方式

1. 取整个包对象，**剔除 `sha256` 字段**；
2. 按 key 排序，紧凑分隔（`separators=(",", ":")`），`ensure_ascii=False`；
3. UTF-8 编码后取 SHA-256 十六进制小写。

Python 等价实现：

```python
import hashlib, json


def sign(pack: dict) -> str:
    payload = {k: v for k, v in pack.items() if k != "sha256"}
    raw = json.dumps(payload, sort_keys=True, ensure_ascii=False, separators=(",", ":")).encode("utf-8")
    return hashlib.sha256(raw).hexdigest()
```

## 6. 导入语义（`diff_pack` / `merge_pack`）

以 **code** 为唯一键，与当前方案逐条比对：

| 状态 | 判定 | 默认勾选 |
|---|---|---|
| `new` | 当前方案没有这个 code | ✅ 是 |
| `conflict` | 同 code 但 名称/热键/分组/备注/间隔 任一不同 | ❌ 否（可手动勾选） |
| `same` | 完全一致 | ❌ 否 |

- 导入只处理**用户在差异表里勾选**的条目；
- 勾选「冲突项覆盖本地」时，冲突项**保留原 id 就地替换**；否则跳过；
- 新增条目分配全新 id，并写入 `source_pack = 包名`、`game = 包适用游戏`；
- 导入成功后把包信息写入配置的 `packs[]`（同名记录去重），可在「已安装」页移除记录；
- 合并函数返回新列表，不修改入参。

## 7. 导出

「⋯ 更多 → 秘籍包管理 → 导出包」：填名称 / 作者 / 适用游戏，选择路径，`make_pack()` 自动补齐 `format` / `pack_version` / `min_app` / `exported_at` / `sha256`。

手写最小可用包：

```json
{
  "format": "vcct-pack",
  "pack_version": 1,
  "name": "我的三件套",
  "cheats": [
    {"code": "ASPIRINE", "name": "满血"},
    {"code": "PANZER", "name": "坦克"},
    {"code": "LEAVEMEALONE", "name": "清除通缉"}
  ]
}
```

## 8. 导入端增强（v1.9.1，不改包格式）

| 能力 | 行为 |
|---|---|
| 热键自动避让 | 导入前在**内存副本**里检查包内热键是否与本地已绑定项、全局暂停键或包内前一条冲突；真冲突时按 F1–F11 → Shift → Ctrl → Ctrl+Shift → Alt 的候选序列改到空闲键，预览表显示新键。合法且未冲突的自定义组合保持原样；候选键用尽则留空由用户手动绑定。导入页可关闭此开关。原文件不会被改写 |
| 包版本比对 | 与本地 `packs[]` 记录按包名比对：首次 / 同名新版本（`pack_version` 更高）/ 内容变化（sha256 不同）/ 完全一致，选包时直接提示。纯本地，不联网、不自动下载 |

> 因为避让只作用于内存副本，包内 `sha256` 仍对应原始文件，比对口径保持一致；校验和不匹配的提示依然只作提醒。

## 9. 边界与免责

- 包只包含**键盘输入的秘籍文本**，不含任何内存读写、DLL 注入、可执行代码；
- 未验证条目请在 `verified: false` 中如实标注；
- 单机专用，请勿用于联机 / 含反作弊环境。
