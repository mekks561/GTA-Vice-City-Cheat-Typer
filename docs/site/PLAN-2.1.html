v2.1 执行方案（P1 收尾，已完成）

基线：v2.0（tag v2.0，commit c07c539） 路线图 docs/ROADMAP-1.7-2.0.md 只规划到 v2.0，本版 = 剩余的 P1 可选项（2.0-I~L） + 兑现 v2.0 未落地的工程承诺。

关键假设

  1. 版本定位：v2.0 已把全部必做做完，v2.1 不开新架构层、不升配置版本（仍 v3）、

不改包格式、不改任何默认行为；只做「补齐 + 修复」。

  1. 2.0-K 的"不联网"口径：跨版本不变量写的是「不读写游戏内存、不联网」。

因此更新入口只调用 webbrowser.open 把 Release 页交给系统浏览器， 程序自身不发起任何网络请求、不下载、不解析版本，且默认关闭。 AST 测试禁止 urllib / requests / socket / http.client 出现在这个函数里。

  1. 2.0-J 的覆盖边界：i18n 覆盖可见控件与菜单；日志、诊断、异常文本保留中文——

译文会掩盖排查线索。语言切换写 settings.locale，重启生效（重建控件比运行时 逐个改更可靠，也不动 Tab 顺序），提供一键重启。

  1. 2.0-I 不自动搬运配置：模式存 exe 旁独立 path-mode.txt，避免"读配置前先知道

配置在哪"的循环依赖；切换只影响下次启动，复制是显式操作且拒绝覆盖、不删原文件。

  1. 2.0-L 不做 PyPI 发布：只让 pip install -e . / vcct 命令真正成立、写清架构约束。

上传 PyPI 需要长期维护承诺与对外发布动作，属 Out of Scope，留给真有人复用时再说。

  1. 2.1-D 的必要性：GUI 子系统（console=False）exe 在交互控制台看不到 stdout，

故新增 console=True 的独立 CLI exe，而不是改主 exe 的形态。
