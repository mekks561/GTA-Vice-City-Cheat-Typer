v2.0 执行方案（通用输入平台，已完成）

基线：v1.9.1（tag v1.9.1，commit 25d4428）｜依据：docs/ROADMAP-1.7-2.0.md 第五章 日历说明：路线图把 v2.0 排在 2027-03-11 冻结期之后，但 1.7～1.9.1 已提前约 4 个月全部交付， 排期约束失效，故按"当前进度"连续开发。

关键实现决策（假设）

  1. 兼容式抽库，不搬文件：直接把 vcct/*.py 移进 vcct/core/ 会让 1.7～1.9 的全部 import、

PyInstaller spec、CLI 同时失效，正是路线图 R2.0.1「抽库演变成重写」的高风险。 因此新增 vcct/core/ 作为门面 + 新能力模块，既有 vcct/*.py 原地保留为实现层。 UI 继续从 vcct.* 导入，行为逐项不变；通用能力一律走 vcct.core。

  1. 配置版本不升级：STORE_VERSION 仍为 3。targets / strategies / hooks_enabled

都是可选字段，缺省 = 旧行为；to_v2() 自然剥离。避免"升版必迁移"的连锁成本。

  1. 默认行为是硬约束（Gate G2.0）：策略默认 fixed（plan_send 与旧 SendParams.for_code

参数完全一致）、钩子默认关闭、targets 缺省空时完全沿用 1.8 的 games 逻辑。

  1. CLI 默认不碰键盘：send 只预演，必须 --execute 才注入，防止脚本误触发把代码打进编辑器。
  2. core 惰性导出：平台相关模块（winapi/hotkeys/tray/importer）用 PEP 562 __getattr__，

import vcct.core 在无桌面/非 Windows 环境不会去加载 Win32 DLL。

  1. P1 未做：2.0-I 便携模式路径选择、2.0-J 多语言 UI、2.0-K 更新提示、2.0-L PyPI 发布——

按路线图属于可选，且 K/L 涉及联网/长期维护承诺，与"不联网"跨版本不变量冲突。
