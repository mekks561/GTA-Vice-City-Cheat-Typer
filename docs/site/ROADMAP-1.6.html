一、版本目标

1.1 一句话定位

v1.6 = 安全阀 + 可诊断 + 可交付。 不堆新功能，把 1.5 已经做出来的能力补齐"出错时怎么办"的三道防线。

1.2 为什么是这个方向（基于代码现状的判断）

现状观察由此得出的问题
2068 行单文件、85 个方法，1.5 一口气加了 7 个功能功能面已够用，继续堆功能边际收益递减
无全局暂停开关（grep 暂停 = 0）安全隐患：热键常驻，在聊天窗口/编辑器里误触即乱打字，只能关程序
无 excepthook、无日志文件（grep 日志文件 = 0）不可诊断：PyInstaller --windowed 下崩溃零输出，用户只能报"打不开"
load_store 解析失败静默回退默认静默丢配置：cheats.json 损坏后用户的自定义秘籍无声消失
无搜索（grep 搜索 = 0），只有分组下拉28 条尚可，用户加到 60+ 条后定位困难
删除无撤销（grep undo = 0）误删方案（含整套秘籍）不可恢复
冲突只标红，无处置手段用户看到"冲突"但不知道换什么键
无 DPI 感知（grep dpi = 0）Win 125%/150% 缩放下 tk 界面模糊，首屏观感差
无 CI，靠人工跑 ruff + unittest每次改动缺少自动回归防线，1.5 曾靠人工抓到 persist 重复定义
远端 0 issue暂无外部需求压力，可自主排期

1.3 成功标准（发布门槛，全部满足才发 1.6）

  1. 暂停状态下按任意秘籍热键 零注入；恢复后立即生效
  2. 任意崩溃/异常在 logs/ 留下可读堆栈；windowed exe 同样有效
  3. 故意写坏 cheats.json 后启动：生成 cheats.corrupt-*.json 副本 + 界面提示，且工具可正常使用
  4. 搜索 + 分组可叠加过滤，Ctrl+F 可直接聚焦
  5. 删除秘籍/方案后可 Ctrl+Z 恢复
  6. 冲突行可一键改到可用键，且不与已有绑定重复
  7. 100% / 125% / 150% 三档缩放截图无模糊、无控件裁剪
  8. 单元测试从 12 条增至 ≥22 条；ruff 0 告警；--selftest 连跑 3 次全过
  9. Release 附带 VC-Cheat-Typer.exe + SHA256 校验文件

二、功能与改进点（按优先级）

P0 — 发布必须（缺一不发）

编号功能具体做法验收标准
P0-A全局暂停 / 紧急停止新增 settings.pause_hotkey（默认 Ctrl+Alt+P，可改，复用现有 HotkeyCapture）；暂停时注销全部秘籍热键，恢复时整体重注册；状态栏与工具栏按钮同步变红；切状态弹 toast暂停后按 F1~F11 无任何字符落地；恢复后正常；暂停键自身冲突时按现有机制提示
P0-B崩溃可诊断sys.excepthook + threading.excepthook → 写 logs/app-YYYYMMDD.log（单文件上限 1MB，保留 3 份）；崩溃弹窗显示日志路径；工具栏加"打开日志"人为 raise 后日志含时间/线程/堆栈；exe 崩溃后日志存在
P0-C配置容错与备份load_store 解析失败 → 原文件改名 cheats.corrupt-<时间戳>.json 并提示；每次 save_store 前把上一版复制为 cheats.bak.json；界面加"从备份恢复"写坏 JSON 后启动不丢原文件、可一键回滚上一版
P0-D搜索顶部搜索框，实时过滤 名称/代码/备注（大小写不敏感）；与分组下拉叠加生效；Ctrl+F 聚焦、Esc 清空；显示"N / 总数"输入 health 命中"满血"；搜索 + 分组交叉结果正确
P0-E单步撤销删除秘籍 / 删除方案 / 批量操作前入栈（仅保留最近 1 步）；Ctrl+Z 或工具栏"撤销"恢复；恢复后自动重新注册热键删方案 → 撤销 → 秘籍与热键全部回原样

P1 — 应该做（进度允许则全做）

编号功能具体做法验收标准
P1-F冲突处置冲突行右键菜单"换一个可用键"：按候选序列（F1–F11 → Shift+F1… → Ctrl+Shift+F1…）逐个试注册，取第一个成功且未被占用的；另有"全部冲突项自动分配"手工占用 F1 后，右键可将该行改到可用键，且列表内无重复

P1-KCI 自动回归.github/workflows/ci.yml：windows-latest，Python 3.10 + 3.12 矩阵，跑 ruff check + unittest + py_compile；README 加状态徽章push 后 Actions 全绿；故意改坏一处能被拦下

明确不做（Out of Scope，避免范围膨胀）

  • 自动更新 / 联网校验 —— 引入网络与签名成本，工具型需求不需要
  • 宏录制、连招序列、多步脚本 —— 偏离"秘籍输入器"定位
  • 多语言界面（仅英文 README 文档）、云同步、账号体系
  • 代码签名证书 —— 成本高于收益，改为"源码可自建 + SHA256"
