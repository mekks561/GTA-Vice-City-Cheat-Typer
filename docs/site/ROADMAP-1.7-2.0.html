二、v1.7 — 输入可靠 + 工程解耦

⚠ 本章部分结论已被代码审计修正，执行以 docs/PLAN-1.7.md 为准。 修正点：① 并发互斥已存在（self.sending Lock，第 1544/2218 行），「交错乱码」不成立，1.7-B 由"修 bug"降级为"补短板"； ② 任务顺序改为先搬后加（搬运营造零差异基线，避免二次搬运）； ③ 不做 CheatApp 类拆分（1200 行 tk 布局代码，搬运风险 > 收益），只抽 5 个无 UI 依赖的叶子模块。

2.1 定位与理由

不新增任何面向用户的功能。 只做两件事：把发送链路做到"可信"（可取消、不交错、不留残键），把单文件拆成包（后续三个版本的改动才有地方落）。 判断依据：连按 F1 F8 两个热键时，两条 worker 线程会同时 SendInput，输出必然交错成乱码——这是当前真实存在的 bug，不是假想需求；而 2900 行单文件已经让 1.6 的「导入方案」按钮截断这类小改都要全文件搜一遍。

2.2 必做（P0，缺一不发）

编号功能做法验收标准估时
1.7-A发送中可取消（承接 1.6 P2-L）发送线程持有一个 threading.Event 停止标志；Ctrl+Alt+P（暂停键）与界面「停止」按钮均置位；取消时必须补发已按下未释放的键（否则 Ctrl 卡住）18 字符秘籍发到第 5 个字符取消 → 后续零输出、无残留修饰键、日志记「已取消 5/18」1.0d

1.7–1.9 做完，这个工具在"VC 秘籍输入"这一件事上已经到顶。2.0 的价值不在功能清单，而在把输入引擎从业务里剥出来：SendInput + IME 绕行 + 热键总线 + 前台判定 这套东西，任何"给按键类游戏/软件注入文本"的场景都能用（GTA 系列之外、老游戏、模拟器、甚至直播时的固定文本）。 2.0 = 可被复用，不是"功能更多"。

三条铁律

  1. 配置只升不降，但必须留出口：任何升版都自动备份上一版文件，并提供显式导出旧格式的命令。
  2. 新字段一律可选：缺省 = 旧行为。允许"程序新、配置旧"，不允许"程序旧、配置新"静默降级（提示升级）。
  3. 迁移函数纯化：migrate_store(raw) -> dict 不碰文件系统，便于用 5 份真实历史配置做回归样本。

6.3 发布纪律（每版相同）

  • tag vX.Y → Release 名称 VC-Cheat-Typer vX.Y（不附加描述文字）→ 资产 exe + SHA256.txt。
  • Release 说明固定含：「从上一版升级：直接覆盖 exe，配置自动沿用/迁移；回退需保留旧 exe + 备份文件」。
  • 每版发布前跑：ruff 0 告警、单测全过、--selftest 连跑 3 次、GUI 冒烟、三档缩放截图（100/125/150）。
  • 1.x 内不做破坏性变更；2.0 允许一次，但必须自动迁移 + 出口 + 三路径实测。

九、累计明确不做（Out of Scope）

沿用 1.6 结论并追加：

  • 界面框架重写（Qt/PySide/Web UI）——2.0 只是把 core 抽出，不换 UI 工具包；
  • 内存修改器 / 修改游戏数据 / DLL 注入——法律与反作弊风险，且偏离"输入工具"定位；
  • 自动更新下载、遥测、云同步、账号体系；
  • 代码签名证书（成本 > 收益，维持"源码可自建 + SHA256"）；
  • 联机 / 含反作弊环境支持（README 永久免责声明）；
  • 宏录制、连招序列、定时循环（2.0 的策略引擎只覆盖"单次输入的质量"，不做自动化脚本）。

十、一句话总结

1.7 把地基浇筑好（拆包 + 输入可信），1.8 把门面做顺（托盘 + 自动切 + 设置页），1.9 把内容做成资产（包 + 批量 + v3），2.0 把引擎抽出来复用（core + 策略 + 目标规则）。 每一版都满足"可单独发布、可安全升级、失败可回退"，不存在"必须等到 2.0 才能用"的功能。
