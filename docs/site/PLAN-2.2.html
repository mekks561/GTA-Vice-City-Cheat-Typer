v2.2「Nova UI」规格与验收标准

基线：v2.1（tag v2.1，commit e5cd779） 本文件是需求规格 + 验收契约，不是事后总结；验收标准在开发前定死，测试按此写。

0. 技术栈取舍（必须先讲清楚）

需求要求「引入新的技术栈、全面重做 UI」。本项目有两条跨版本不变量：

  1. 零第三方运行时依赖（CONTRIBUTING.md §3 / 路线图 §8）；
  2. core 零 GUI 依赖、UI 不直接调 Win32。

同时路线图 §9 明确把「界面框架重写（Qt / PySide / Web UI）」列为 Out of Scope。

若引入 PySide6 / QtWebView：exe 会从 ~10 MB 涨到 60 MB+、需要打包 Qt 运行时、CI 要装依赖、 pip install -e . 的 dependencies=[] 失效、208 条 GUI 冒烟与三产物形态全部要重做，且不可回退。 这与「保持核心业务流程稳定」和「失败可回退」直接冲突。

因此本版引入的"新技术栈"是项目自研的 UI 基础设施层 vcct/ui/：

层技术说明
设计令牌theme.py单一数据源：颜色 / 间距 / 字号 / 圆角 / 密度；浅色 + 深色双主题；WCAG 对比度计算
组件components.py声明式组件工厂：卡片、胶囊、分段控件、空状态、命令栏、状态条
布局shell.py新骨架：侧边导航 + 顶部命令栏 + 内容区 + 底部状态中心
交互commands.pyCtrl+K 命令面板（模糊匹配 + 纯键盘执行）

它是新的 UI 架构范式（令牌驱动 / 声明式 / 命令优先），仍是标准库 + tkinter/ttk， 不新增任何 pip 依赖，不改动 vcct/core/，并且保留 --classic-ui 一键回退到 1.7～2.1 的布局。

若确需 Qt / WebView，属于重新立项：需用户显式确认接受「放弃零依赖、放弃可回退、重做发布形态与 CI」， 应另起 v3.0，不在 2.2 内夹带。

1. 升级目标

#目标可衡量结果
G1视觉现代化从 1.7 的「工具条 + 表格」升级为令牌驱动的卡片式布局；浅/深双主题；所有颜色出自单一令牌表
G2命令优先常用操作不必层层找菜单：Ctrl+K 命令面板覆盖 ≥20 个既有动作，全程键盘可达
G3信息层级侧边导航把「秘籍 / 热键 / 内容 / 数据 / 帮助」分区；底部状态中心聚合游戏、热键、发送状态
G4核心零改动发送引擎、热键注册、托盘、包、迁移链、CLI 一行不改；UI 只调用既有业务方法
G5可回退--classic-ui / settings.ui_mode=classic 恢复 1.7～2.1 原布局与配色；升级零感知

明确不做：不换 UI 工具包、不改配置版本（仍 v3）、不改包格式、不联网、不写游戏内存、不做动画堆砌。

3.3 命令面板（新交互）

  • 触发：Ctrl+K（全窗口）/ 顶栏按钮；Esc 关闭、↑↓ 选择、Enter 执行、输入实时过滤
  • 数据源：commands.py 的 CommandRegistry，每条命令绑定一个既有 CheatApp 方法
  • 覆盖 ≥20 项：添加/编辑/删除/发送/停止/暂停/重注册热键/热键总览/设置/向导/

导入包/导出包/文本导入/模板/批量操作/环境诊断/发送历史/清空统计/恢复默认/检查更新/切换主题

  • 模糊匹配：子序列匹配 + 中文/英文关键词，不依赖第三方库

5. 验收标准（可量化，测试即契约）

5.1 视觉一致性

#标准自动化验证
V1所有颜色来自 theme.py 的令牌表；除 theme.py（令牌源）外，新 UI 模块内零硬编码 #RRGGBBAST + 正则扫描 vcct/ui/*.py
V2正文/背景对比度 ≥ 4.5:1（WCAG AA），主按钮文字 ≥ 4.5:1contrast_ratio() 计算并断言，浅/深两套主题都测
V3浅/深主题令牌键集合完全一致，切换不缺键set(light) == set(dark)
V4间距/字号按密度令牌统一，组件不自行写死 padx/pady 魔数组件从 tokens.spacing 取值；测试断言缩放线性
V5100% / 125% / 150% DPI 三档下无控件裁切ui_scale() 三档构建冒烟（人工截图复核项）

5.2 交互流畅度

#标准自动化验证
I1命令面板输入到结果刷新 < 50 ms100 次输入计时取 P95
I2全键盘可达：Ctrl+K → 输入 → ↑↓ → Enter → Esc事件模拟测试
I3主题/密度切换 < 200 ms，且不重建业务控件树计时 + 断言 self.tree 对象身份不变
I4无主线程阻塞：发送仍在工作线程；命令面板不 sleepAST 禁止新 UI 模块出现 time.sleep / update() 死循环
I5两种 UI 模式下所有业务方法可调用且不抛异常GUI 冒烟分别构建并调用若干命令
